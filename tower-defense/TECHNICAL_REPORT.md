# 《堡垒防线 TD》网页塔防完整项目技术报告

## 1. 项目概述与交付形态

《堡垒防线 TD》是一款基于原生 ES Modules、HTML5 Canvas 2D 与 Web Audio API 构建的经典网页塔防游戏。项目采用**零构建工具、零外部运行时 npm 依赖**的轻量级前端工程架构，同时提供两种交付形态：

- **模块化源码工程**（`index.html`、`styles/`、`src/`、`tests/`）：职责清晰、仿真引擎与浏览器 DOM 完全解耦，支持 Node.js 原生测试框架直接运行自动化回归测试。
- **单文件直开版本**（`dist/tower_defense_standalone.html`）：内联全部样式与脚本，双击即可在任意现代浏览器离线游玩，无需启动本地服务器。

---

## 2. 系统架构与模块职责

项目采用经典的 **Simulation-Renderer-Controller（仿真-渲染-控制）三层解耦架构**，核心数据流单向流动：用户输入经由 `main.js` 调用 `GameEngine` 状态变更方法，`GameEngine` 通过事件回调（`onEvent`）通知音效、HUD 与弹窗，而 `GameRenderer` 在 `requestAnimationFrame` 主循环中以只读方式渲染当前帧状态。

| 模块路径 | 代码行数 | 核心职责 | 运行环境 |
| --- | ---: | --- | --- |
| `src/config.js` | 190 | 网格常量、3 张地图路径、5 种炮塔 3 级数值表、8 种敌人属性、波次与无尽模式生成器 | 浏览器 / Node.js |
| `src/engine.js` | 600 | 无头核心仿真引擎（网格占位、建塔/升级/出售、索敌、弹道/射线/连锁/溅射、分裂/治疗、胜负与无尽状态机） | 浏览器 / Node.js |
| `src/renderer.js` | 423 | Canvas 2D 战场渲染、DPR 自适应缩放、屏幕坐标到网格映射、塔体旋转/后坐力/光束/粒子绘制 | 浏览器 |
| `src/audio.js` | 156 | Web Audio API 程序化合成音效（12 种战术与 UI 音效 + 高频节流 + 静音开关） | 浏览器 |
| `src/main.js` | 474 | HUD 绑定、炮塔建造面板、属性检查器、快捷键（`1-5`/`Space`/`F`/`U`/`S`/`Esc`）、本地最高波次持久化 | 浏览器 |
| `index.html` + `styles/main.css` | 285 | 响应式双栏布局、毛玻璃面板、暂停与结算弹窗 | 浏览器 |
| `tests/engine.test.mjs` | 323 | 基于 Node.js `node:test` 的 12 项单元与端到端自动化测试套件 | Node.js 18+ |

## 3. 核心算法与数值设计

### 3.1 网格拓扑与路径展开算法

战场采用 `16 × 10` 逻辑网格（单格 `60 × 60 px`，逻辑画布 `960 × 600`）。每张地图通过稀疏拐点数组（`waypoints`）定义 1 条或 2 条路径，初始化时 `buildMapGeometry()` 沿曼哈顿步进展开为 `Set<"c,r">` 路径集合 `pathTiles` 与像素中心点序列 `pixelPaths`：

- **蜿蜒峡谷（canyon）**：单线 S 型长路径，初始金币 `160`，适合交叉火力教学。
- **十字要塞（crossroad）**：单线中区折返路径，初始金币 `170`，强调中心区域范围塔收益。
- **双线突围（twin）**：上下双入口在 `(11, 5)` 汇合直逼核心，初始金币 `190`，敌人在双线间交替分配出生（`pathToggle % pixelPaths.length`）。

建塔校验 `isCellBuildable(c, r)` 通过 `O(1)` 集合查表同时检查边界、路径占用与已有炮塔冲突。

### 3.2 防御塔机制与经济模型

游戏设计了 5 类定位互补的防御塔，均支持 Lv.1 → Lv.2 → Lv.3 升级，出售按累计投入的 `70%`（`Math.floor(invested * 0.7)`）返还金币：

| 炮塔名称 | 造价 | 升级花费 (Lv.2 / Lv.3) | 攻击机制与战术定位 |
| --- | ---: | ---: | --- |
| 机枪塔 (`gatling`) | 50 | 45 / 85 | 高射速单体动能弹（3.1 → 4.8 发/秒），前期高性价比主力 |
| 冰霜塔 (`frost`) | 75 | 60 / 105 | 范围溅射减速（移速系数 0.62 → 0.38，持续 2.0–3.0 秒），核心控场 |
| 加农炮 (`cannon`) | 100 | 80 / 140 | 重型榴弹大范围 AOE 溅射（半径 68 → 98 px），克制密集敌群 |
| 电磁塔 (`tesla`) | 120 | 95 / 160 | 瞬发连锁闪电（3 → 5 跳，逐跳衰减系数 0.85），无视护甲 |
| 棱镜激光 (`laser`) | 135 | 110 / 185 | 远程持续锁定射线（无视护甲），连续锁定 3 秒内伤害线性提升至 150% |

### 3.3 索敌策略与伤害结算

每座炮塔支持 4 种实时切换的索敌模式：

- `first`（最前）：选取射程内 `distTraveled` 最大的敌人，优先拦截逼近核心的目标。
- `strong`（最强）：选取当前 `hp` 最高的敌人，适合激光塔集中击杀重甲与 Boss。
- `weak`（最弱）：选取当前 `hp` 最低的敌人，适合快速补刀收割残血。
- `close`（最近）：选取欧氏距离 `Math.hypot(e.x - t.x, e.y - t.y)` 最近的敌人。

伤害公式统一经过护甲折减结算：`dmg = Math.max(1, rawDmg * (1 - (armorPierce ? 0 : enemy.armor)))`。其中 `tank`（重甲兵）拥有 `35%` 护甲，`boss`（毁灭者）拥有 `30%` 护甲，`splitter`（分裂体）拥有 `10%` 护甲。

### 3.4 敌人生态与波次难度曲线

项目内置 8 种敌人（侦察兵、步兵、疾行者、重甲兵、分裂体、子体、治疗师、毁灭者 Boss），包含两类特殊战场技能：

- **死亡分裂**：`splitter` 被击杀时在当前路径段位置立即生成 2 个高移速 `mini` 子体。
- **群体治疗**：`healer` 每 2.6 秒触发一次半径 `85 px` 的治疗光环，为范围内受伤友军恢复 `14%` 最大生命值。

前 15 波采用手工编排的战术组合（第 5、10、15 波刷出 Boss），生命值倍率线性增长 `1 + (wave - 1) × 0.18`；通关第 15 波后可选择进入**无尽模式**，生命倍率转为指数增长 `(1 + 14 × 0.18) × 1.22^(wave - 15)`，且每 5 波追加 Boss 群。此外，在当前波次全部出兵完毕后点击提前出兵可立即获得 `+15` 金币奖励。

## 5. 性能、健壮性与兼容性设计

1. **倍速子步进（Sub-stepping）防穿模**：在 `2x` 倍速模式下，主循环并非将 `dt` 简单乘以 2，而是以单帧 `rawDt`（上限钳制为 `0.05s`）连续执行 2 次 `engine.step(rawDt)`，避免高速子弹跳过碰撞半径或敌人越过路径拐点。
2. **高分屏 DPR 自适应**：`GameRenderer.resize()` 读取容器尺寸并按 `Math.min(devicePixelRatio, 2)` 设置物理像素分辨率，再通过 `ctx.setTransform` 映射至 `960 × 600` 逻辑坐标系，兼顾清晰度与 GPU 填充率。
3. **音频节流与手势解锁**：`SoundEngine` 仅在首次用户点击后惰性初始化 `AudioContext`，并对高频发射音效施加 `45ms` 节流窗口，防止密集火力导致波形削波失真。
4. **安全持久化**：`localStorage` 读写全部包裹在 `try/catch` 中，确保在隐私模式或受限沙盒 iframe 环境下零异常降级。

## 6. 后续可扩展方向

- **地图编辑器与自定义 JSON 关卡**：利用当前稀疏拐点配置结构，可快速扩展可视化网格路径绘制与导入导出功能。
- **炮塔科技树与分支进化**：在 `TOWER_TYPES.levels` 中引入 Lv.3 二选一分支（如冰霜塔分支为「绝对零度冻结」或「大范围暴风雪」）。
- **对象池优化**：在无尽模式后期（>30 波）可为粒子与弹道引入对象池，进一步降低短生命周期对象的 GC 抖动。
